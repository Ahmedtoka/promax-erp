# PROMAX ERP — نظام إدارة التوزيع

Laravel 12 + MySQL. بيشغّل لوحة الإدارة والعمليات، وبيخدم الموبايل أبلكيشن عن طريق API.

---

## التشغيل من الصفر

```bash
cd C:\xampp\htdocs\ProMax\Promax-erp

composer install

# الداتابيز اسمها promax (موجودة في .env) — اعملها في phpMyAdmin لو مش موجودة
php artisan migrate:fresh --seed

# لينك المرفقات (صور الأماكن والأوراق الرسمية) — مرة واحدة بس
php artisan storage:link

php artisan serve
```

افتح `http://127.0.0.1:8000` → هيوديك على شاشة الدخول.

### الحسابات

> ⚠️ **مافيش حسابات ولا باسوردات مكتوبة هنا.**
> كان مكتوب في المكان ده باسورد `promax123` وقايمة إيميلات — والملف
> ده مرفوع على الجت، يعني أي حد شاف الريبو معاه بيانات دخول السيستم
> الشغّال. الحسابات بتتعمل بأمر، والباسورد بيتولّد عشوائي وبيتطبع في
> الترمينال مرة واحدة:
>
> ```
> php artisan promax:catalogue --force     # المخازن والمنتجات
> php artisan promax:team:setup --force    # الفريق — بيطبع الباسورد المؤقّت
> php artisan promax:password <الإيميل> --password=<باسورد قوي>
> ```
>
> ولو الدخول مش شغّال: `php artisan promax:doctor`


## الداتا

`php artisan migrate:fresh --seed` بيشغّل 3 سيدرز بالترتيب:

1. **PromaxImportSeeder** — بيرحّل داتا PROMAX الحقيقية من `storage/app/data/promax.json`:
   103 عميل بتصنيفاتهم وأرصدتهم، 21 عقد، ~2000 حركة كشف حساب، 23 صنف بالتسعيرات الثلاثة والمخزون، و4 زونز
2. **TeamSeeder** — المستخدمين بالرولز + توكنات الأبلكيشن
3. **FieldDaySeeder** — يوم شغل: عهدة 3 عربيات، زيارات وفواتير، 5 أوامر توريد، وطلب عميل جديد مستني

## الـ API (للموبايل أبلكيشن)

المصادقة: `Authorization: Bearer <token>` — التوكن بيرجع من `/api/login`.

| Method | Endpoint | الوظيفة |
|---|---|---|
| GET | `/api/ping` | فحص السيرفر |
| POST | `/api/login` | `{login, password}` → توكن + بيانات المستخدم |
| GET | `/api/bootstrap` | كل حاجة: العهدة، الزونز والعملاء، الـ POs، إحصائيات اليوم، الإشعارات، التراكينج |
| POST | `/api/visits/check-in` | `{client_id, lat, lng}` |
| POST | `/api/visits/{id}/check-out` | قفل الزيارة |
| GET/POST | `/api/invoices` | فواتير اليوم / إنشاء فاتورة |
| POST | `/api/pos/{id}/arrive` | الكورير وصل المكان |
| POST | `/api/pos/{id}/deliver` | تسليم + خصم من العهدة |
| POST | `/api/client-requests` | تسجيل عميل جديد |
| POST | `/api/notifications/read` | تعليم الإشعارات كمقروءة |

### API المدير (أدمن / Channel Manager)

| Method | Endpoint | الوظيفة |
|---|---|---|
| GET | `/api/manager/bootstrap` | إحصائيات اليوم + كل المناديب + الطلبات + تحركات الفريق |
| GET | `/api/manager/reps/{id}` | تفاصيل مندوب: عهدته، فواتيره، أوامره، تراكينجه |
| POST | `/api/manager/requests/{id}/decide` | `{decision, discount?, note?}` — موافقة/مراجعة/رفض |

### قواعد الشغل المطبّقة في الـ API

- الفاتورة بتخصم من عهدة العربية تلقائي، ولو الكمية مش متاحة بترفض
- خصم عقد العميل بيتحسب تلقائي على الفاتورة
- العميل تصنيفه `danger` (تحصيل فوري) → البيع الآجل مرفوض
- الفاتورة الكاش بتسجل قيدين: مبيعات + تحصيل (الرصيد يفضل صفر)
- الفاتورة الآجل بتسجل قيد مبيعات بس (الرصيد بيزيد)
- تسليم الـ PO بيخصم من العهدة وبيسجل قيد على حساب العميل
- ممنوع تشيك إن على عميل وفيه زيارة تانية مفتوحة
